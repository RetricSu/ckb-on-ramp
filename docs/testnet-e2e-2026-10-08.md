## 联调发现及修正

1. 原网页代理写死 `testnet.ckb.dev/rpc`，本机多次遇到 TLS 建连中断、返回空 500，导致 WASM 解析链依赖或组装 funding 失败。网页代理现使用与 API 相同的 `CKB_RPC_URL`，保留同源访问和原安全头；本轮使用仅绑定 localhost 的真实 RPC 转发器，以 Node fetch 连接 `https://testnet.ckbapp.dev/`。它只重试只读 `get_*` 请求，不重试交易广播、不模拟任何链数据。
2. 首次关闭已在链上成功，WASM 的 `include_closed` 结果却停在 `SHUTTING_DOWN / WAITING_COMMITMENT_CONFIRMATION`，未暴露 `shutdown_transaction_hash`；原 UI 确认函数超时。精确的 WASM 内部原因未确认。新增只读 `/api/channels/:channelId/close`：必须有原 durable session，native FNN 的 channel id、peer 都匹配且状态为 `Closed / COOPERATIVE`，才返回关闭 hash。客户端随后验证链上 input、目标钱包 lock、cWBTC 类型及金额；不因运营方报告 hash 就宣称成功，不创建 session 或授予签名权限。
3. 原持久化单测的清理钩子可能清空默认运行 session 文件。该测试现先切换内存 store；真实联调另用独立 `BOOTSTRAP_STORE_PATH`。不从 FNN 或历史证据重建丢失的签名授权。

## CCH 的实际阻塞

独立 CCH 没配置 `fiber.chain` 时默认按 devnet 校验，拒绝 `fibt`：`expected fibd, got fibt`。配置 `fiber.chain: testnet` 后，真实 LND regtest hold invoice 仍被拒绝：`encoded currency is Regtest, expected BitcoinTestnet`。

[Fiber v0.9.0 源码](https://github.com/nervosnetwork/fiber/blob/e6cb7ac/crates/fiber-lib/src/cch/actor.rs) 明确映射 `Fibt → BitcoinTestnet`、`Fibd → Regtest`。因此旧 HANDOFF 的“CKB testnet + 本地 Bitcoin regtest”属于历史记录，不能作为当前 v0.9.0 的复现步骤。没有改前缀、替换发票或关闭网络校验。

已尝试创建独立 Bitcoin testnet Neutrino LND，先用官方安装指南的 `faucet.lightning.community`，再用维护者列出的 `btcd-testnet.lightning.computer` 与 `lnd.bitrefill.com:18333`。本次观测仍为 `peers:[]`、`block_height:0`、`synced:false`，无法得到可付款的 testnet Lightning 通道。来源：[LND 安装指南](https://github.com/lightningnetwork/lnd/blob/master/docs/INSTALL.md)、[维护者运行指南](https://github.com/alexbosworth/run-lnd)。

下一步需要同步完成、具备入向/付款流动性的 Bitcoin testnet LND。接入后再验证真实 CCH 订单 Success、付款中刷新、已成功订单刷新；本轮不能将这些订单场景标为通过。

## 复现配置与检查

- 所有测试数据和密钥在 gitignored `ops/data/testnet-e2e/`，`.env` 亦不提交。浏览器只操作测试运行器自己的 profile。不要打印或提交 `fiber/sk`、`ckb/key`、LND macaroon、API 私钥。
- FNN RPC `127.0.0.1:8229`、P2P `/ip4/127.0.0.1/tcp/8230/ws`、CCH `127.0.0.1:8227`、测试 API `3011`、测试 Vite `5175`。只绑定本机，不覆盖用户已有 3001/5173 服务。
- 用 `fiber-pay --data-dir <task-data-dir> config init --network testnet --rpc-port 8229 --p2p-port 8230 --proxy-port 8231`，使用 v0.9.0 binary；配置 `fiber.chain:testnet`、WebSocket 监听、cWBTC whitelist（脚本及 Cell dep 与 `FiberProvider.tsx` 完全相同）。RPC modules 包含 `channel,payment,graph,info,invoice,peer,watchtower,pubsub`，CCH 依赖 pubsub。
- `offckb deposit <testnet-address> 10000 --network testnet` 领取 CKB。该 CLI 会默认打印临时私钥，运行时屏蔽日志。通过项目 cWBTC faucet 的 `/api/claims` 领取 100 cWBTC，随后查询 claim 状态及真实交易确认。
- FNN cWBTC 出资 Cell 必须精确为 `100000000` raw，每个 capacity ≥184 CKB，本轮预拆为 200 CKB；赞助钱包用 `node ops/prep-gift-cells.mjs --count 8 --amount 220`。FNN 钱包和 API 赞助钱包为不同测试钥，浏览器不获得它们。
- `.env` 配置 `FNN_RPC_URL`、`CCH_RPC_URL`、`CKB_RPC_URL`、`OPERATOR_CKB_PRIVATE_KEY`、`OPERATOR_CHANNEL_FUNDING_AMOUNT=100000000`、独立 `BOOTSTRAP_STORE_PATH`。DEV password 只用于自动化测试，生产仍使用现有 passkey 路径。
- 直接 Fiber 验证：浏览器 `newInvoice({amount:'0x3e8',currency:'Fibt',udt_type_script:CWBTC_SCRIPT,hash_algorithm:'sha256',final_expiry_delta:'0x5265c00'})`；`fiber-pay --data-dir <operator-dir> payment send --invoice <fibt-invoice> --json` 后轮询真实付款/通道余额至结算。CLI 的 queued/pending 响应不算付款成功。
- `fiber-pay --data-dir <operator-dir> invoice create --amount 100 --udt-name cWBTC --json` 创建付款发票；UDT amount 为 raw 整数，不是 100 个 cWBTC。浏览器执行现有 Spend 函数，确认 `get_payment` Success 与余额 900，再协作关渠。
- 复核关闭：读取已知通道的 `/api/channels/<id>/close`；通过 CKB RPC `get_transaction` 验证 committed、原 funding input、收款 lock、900 raw cWBTC。私钥不用于证据文件。

本轮新增关渠回退、错误 peer/channel/状态/哈希及错误链上 input/收款人/资产/金额回归。全量 202 项测试通过（87 API + 114 web + 1 contracts），typecheck、build 通过。后续最终确认见 HANDOFF；最终交付接受由人类完成。
